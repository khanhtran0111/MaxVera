# Reproduction protocol v2

Input: canonical 120-row IRIS v1 dataset, commit `698fb7248ae30cb7f7782d59c841f05ad70ea9cc`; IRIS commit `67140e84e6a01da2b44803a6208be2ea7bd4bd51`. This track is **oracle-CWE / model-substituted reproduction**. The analyzer may read oracle metadata here. Never share its query/spec/prompt caches with research.

Public entrypoint: `python -m maxvera pipeline reproduce --config configs/pipelines/reproduce.yaml --mode full --run-id <new-id> --execute`. The migration initially used dry-run only. A later user-authorized full run is now active; see the [current execution record](reproduction_full_2026-10-21.md). No completed full result is claimed. Omitting `--execute` uses the configured dry-run default. `--dry-run` never contacts a model, builds a project, or creates a run.

The DAG executes prepare → database, then independent CodeQL reference and IRIS branches. The IRIS branch invokes the original candidate extraction, API/parameter labeling, query construction, taint analysis, postprocessing and contextual filtering methods. It never invokes upstream `evaluate_result`. Each reference branch has its own class/method inventory so IRIS failure does not prevent reference scoring.

Stage outputs and status are checkpointed per opaque case. All selected cases, including fetch/build failures and pending cases after interruption, remain accounted for. A run with any failed branch is `COMPLETED_WITH_CASE_FAILURES`, exit 1. A run with no findings can succeed. Config/schema/source/code/tool changes reject resume. A completed run is immutable; `--resume` verifies checksums. Interrupted paid stages are marked `UNCERTAIN_REMOTE_CALL`; inspect their private request journal before adjudicating a retry. A validated successful journal response is replayed without a second model call. JSON syntax/shape validation is independent of the transport response-format flag, preserving original top-level arrays. A cost-budget violation creates a durable stop before any response can be replayed or used in a later stage.

## Current runtime profile

The active user-authorized fast run uses `configs/pipelines/reproduce_fast.yaml`, extending `configs/runtime_fast.yaml` and selecting `configs/models/gpt_oss_20b_openrouter_fast.yaml`. Set the process environment `MAXVERA_OPENROUTER_PROVIDER=groq` for this profile; no credential change is required. The original AkashML configuration remains available as the historical condition.

The fast profile retains GPT-OSS-20B, the same sampling/prompt/token caps, one project and one LLM request at a time, and the existing per-case budgets. It removes the fixed 30-second post-completion idle and uses 1–30-second exponential429 backoff, respecting a longer numeric Retry-After. Provider/quantization is an experimental condition: Groq is a new fixed route, not silently mixed with AkashML. Use a fresh run and empty journal; pacing fields participate in request keys, so do not switch profiles inside an existing journal.

A single JSON Markdown fence is accepted without changing the saved answer; strict JSON content/type/duplicate-key/nonfinite validation remains. If upstream catches a model transport/budget error, the stage fails and later batches cannot make more calls. Partial output from such a stage cannot be published as successful analysis. See the [execution record](reproduction_full_2026-10-21.md) for measured diagnostics and limits.

## Fidelity and deviations

- Canonical model: `openai/gpt-oss-20b`; existing OpenRouter transport pins provider and rejects model/provider mismatches. Routing requires supported parameters and disables fallback. The migration used no network model check; later isolated live checks passed for the pinned route, as recorded in the [response repair report](llm_response_repair_2026-10-21.md). This does not guarantee future provider availability.
- The installed patched IRIS toolchain reports **2.15.5**, not the plan's provisional 2.15.3. Research reports 2.26.2. Both are recorded by doctor and execution fingerprints. Prior smoke attempts exercised real compilation/queries but did not finish both cases. After response repair verification, the user authorized full execution without repeating smoke for that repair; exact paper parity is still unproven.
- Original source/sink/context prompt methods and oracle CWE are retained. Requests are sequential. API batch size 30 and parameter batch size 50 match the upstream defaults. `use_exhaustive_qll=True`, local README loading, package-name aliases, hosted sampling/output budgets, journal caching and bounded identical-prompt JSON retries are explicit adapter deviations.
- The default new reproduction uses original patched queries. `modern_2_26` mechanically changes queries and is a different fidelity condition. It must not be reported as exact IRIS v1 semantics.
- Preserve raw prompts/responses/specs/SARIF privately. Run directories are mode 0700. Secret values never belong in manifests. Runtime failures redact bearer/API credentials.
- Received HTTP 200 envelopes are checked for provider errors, empty/truncated content and route drift before acceptance. Private response bodies retain generation evidence. Known-cost transient unusable output can retry within the existing ceilings; unparseable/uncertain responses, refusals and permanent errors stop. Cached output is revalidated without bypassing old pending journals. See the [response repair report](llm_response_repair_2026-10-21.md).
- Cost accounting uses returned provider usage. Unknown cost blocks subsequent requests; no claim of invoice-equivalent or hard prepaid dollar control is made. Conservative UTF-8 token reservations may stop below actual token capacity.
- The earlier AkashML live-run timing policy waits30 seconds after each completed response, uses a 1,800-second request timeout, an 86,400-second reproduction case deadline and a 1,800-second reference-query timeout. The completion timestamp is durable across worker/stage restarts; cached response replay makes no request and does not wait.
- Explicit HTTP 429 rejections retry the identical prompt with configurable exponential backoff (currently 60–600 seconds). A longer numeric provider Retry-After is honored instead of shortened to the local cap, within the remaining time budget. Rejected attempts count toward the call limit and release unconsumed token reservations. Network failures and other uncertain responses still stop for journal inspection; they are never automatically retried. The earlier timing-only change retained monetary/call/token ceilings. The subsequent r4 repair overrides reproduction ceilings to 1,000 attempts, 8,000,000 input reservation units and 2,048,000 output reservation units with the same USD 1 monetary setting. A known batch must fit its minimum uncached work before any request is sent; retries and later stages retain per-request enforcement.

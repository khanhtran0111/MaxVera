# Research protocol v2

Public entrypoint: `python -m maxvera pipeline research --config configs/pipelines/research.yaml --variant graph_only --mode full --run-id <new-id> --execute`. This full command has **not** been run. Default configuration selects the existing 96-project development split from `D_extended`; it must not use the disjoint IDs from `D_repro_v1`. The benchmark is already seen/development data; do not claim held-out generalization.

## Firewall and snapshots

`dataset prepare` is trusted data preparation and may read labels. `--sources` explicitly fetches pinned vulnerable sources, applies the existing dataset build patches and materializes opaque snapshots with generic build commands. It strips Git/build/patch files, rejects symlinks and hashes source content. Preparation may require network access and substantial storage; it was not run with `--sources` during migration.

The research worker runs under Linux Landlock ABI >=3 with a read and filesystem-mutation allowlist for `analysis_input`, runtime libraries, source modules and pinned toolchains as read-only inputs. Only the current run and its private build/cache directories are writable. It receives a filtered environment and no `.env`. It cannot read or overwrite `evaluator_only`, canonical manifests, raw metadata, reproduction output or other runs; symlink escape is denied. Unavailable Landlock fails closed. This is a filesystem leakage boundary; it is not a general hostile-code or network isolation sandbox.

Snapshots and metadata must already exist before research execution. Source fingerprints enter resume identity. A single inventory policy excludes Git/Gradle/build products. Builds run in a private copy; modified and generated source files are recorded, and graph provenance hashes the actual analyzed copy rather than pretending it is the unchanged input snapshot. Original source/CVE/advisory comments are not accepted as evidence blindly: analyzer output rejects CVE identifiers. Generic catalogue CWE families are allowed and fixed for every project.

The [24 October readiness repairs](research_readiness_2026-10-24.md) add a read-only input preflight before research execution, validating all selected snapshots and usable build recipes. Preparation writes versioned source/provenance manifests atomically, reuses verified snapshots and preserves legacy snapshots requiring independent audit. Full build identity remains bound to database/evidence integrity; separate semantic identity binds repository inputs and generated Java, excluding runtime/cache metadata. `research_full120.yaml` selects all 120 IDs while the default development profile preserves its 96-case split.

## Graph and discovery

Custom CodeQL queries reuse the typed `Grounding.qll` infrastructure, extracting source-backed expression/parameter nodes, local conservative taint steps, argument-to-parameter edges and return-to-call edges. Node keys include span, expression kind and enclosing callable; overloads and shared spans cannot silently merge.

Graphs use deterministic JSONL adjacency data and graph hashes. Schema/provenance distinguish extracted facts from verified vulnerability claims. Static dispatch can miss overrides, lambdas, exceptions or external summaries; unresolved calls/partial build rate are explicitly unknown rather than fabricated zero. Current graph quality reports type counts, cross-file/orphan counts and provenance coverage. Maximum node/edge bounds fail explicitly. Traversal is bounded to five hops by default; `research.max_traversal_nodes` defaults to 4096 visited nodes per endpoint. Discovery persists cap/truncation diagnostics and marks affected candidates. Shortest paths are retained; additional alternatives may be missed. Neighbor/rank tie ordering uses canonical program points, preserving semantic Top-K across volatile build metadata changes. Expanded varargs use argument-to-parameter position mapping.

Generators: generic CodeQL alerts, sink backward slicing and source forward slicing. Independent graph generators can produce a candidate when default alerts are empty. The versioned default-alert coverage rule compares source and sink file/line spans; graph evidence covered at both endpoints shares attribution with the alert and does not add a duplicate Top-K entry. This is a conservative coverage association, not proof that taint models or exploitability are equivalent. Candidate paths remain pre-verification hypotheses; CALLS alone cannot become dataflow. Candidates retain stable evidence IDs, locations, source origins and deterministic rank features. Scores are uncalibrated ranking values. Location-only static alerts are weak evidence; CodeQL code-flow results are recorded distinctly.

`static_only` and `graph_only` execute without a model. Disabled stages record `SKIPPED_BY_VARIANT` and do not emit fake LLM/verification files. `graph_llm` and `graph_llm_verify` support at most two smoke cases. The default full LLM policy requires `research.graph_signal_approved: true` after review of measured frozen development evidence. A separate prospective exploratory protocol may be registered with `experiment register` after real paired fixed-pilot static/graph evaluation. It binds the complete configured cohort, input inventories, implementation, executable tool/runtime contents, effective model parameters and frozen development evidence. `--experiment-protocol` permits that explicitly scoped execution while approval remains false; it does not satisfy the confirmatory expansion gate or repair unknown truth. This amendment preserves the original specification's allowance for negative results. See the [full runbook](research_full_runbook_2026-10-24.md). `text_only` remains **NOT_IMPLEMENTED**.

## Bounded reasoning and verification

The pre-LLM candidate pool, scores and ranks remain frozen. Static alerts pass the same source boundary with explicit external/mixed-path accounting; unsafe paths and changed known source bytes fail closed. Retrieval uses the analyzed source snapshot and graph, checks source hashes, bounds code spans and the serialized prompt, and emits content-addressed evidence bundles. Required graph endpoints or static first/last anchors must remain visible as actual code, including available columns. Missing or clipped endpoint evidence produces `INCOMPLETE_EVIDENCE`, retains the candidate and sends no paid request. Interior context truncation remains explicit. The model must return the same candidate/bundle IDs and cite actual bundle evidence IDs. Citation existence is validated; semantic correctness of the rationale still needs review, including consistency between verdict and rationale. Valid assessments apply only a soft score delta of -1, 0 or +1. Invalid responses and provider failures retain candidates as uncertain and invalidate aggregate post-LLM recall rather than appearing as a complete rerank.

The trusted parent loads the configured model/profile and passes credentials through worker stdin. Credentials are not written to resolved config or inherited through the worker environment. Research requests use private, research-scoped journals and the existing call/token/cost-stop controls. A configured dollar stop threshold is not a provider-side prepaid cap; unknown costs stop subsequent calls.

An absolute case deadline now covers request spacing, backoff and transport/response reading. It is independent of paid cache identity. The Linux sequential worker enforces the transport deadline with a main-thread process timer and restores any later pre-existing alarm. Ambiguous interrupted charges remain uncertain and cannot be automatically replayed. Every frozen research run additionally writes `quality_report.json`; engineering acceptance is separate from stage/run completion and does not approve the scientific signal or full120 readiness.

Targeted verification requires frozen, source-backed graph endpoints with explicit source/sink roles and exact spans. Generated CodeQL queries first check that each endpoint resolves uniquely in the private database, then run modeled global taint reachability. Results include `FLOW_FOUND`, `NO_FLOW_FOUND`, `UNSUPPORTED_SPEC`, `QUERY_INVALID` and `TIMEOUT`. All candidates remain in final output. No-flow is never safety; a flow is static model evidence, not verified exploitation. These generic queries do not implement CWE-specific sanitizer/barrier templates.
